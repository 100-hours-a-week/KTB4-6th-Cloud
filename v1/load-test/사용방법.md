## 이번 테스트: 15 → 20 → 50 → 100팀

팀당 6명 기준입니다. 아래 명령은 `project/load-test`에서 실행합니다. 먼저 실제 테스트 대상 API 주소를 설정합니다.

```bash
cd project/load-test
mkdir -p reports
API_URL=https://api.example.com
```

각 규모는 **새 계정과 새 팀**을 사용합니다. 네 규모를 모두 실행하면 총 185팀이 생성됩니다. 회원·팀 생성은 준비 스크립트가 순차 실행하며, HTML 결과는 k6로 측정하는 회의 생성·참여 요청에만 생성됩니다.

### 1. 회원 생성·팀 생성·팀 가입: `prepare-teams.py`

필요한 규모의 명령만 실행합니다. 출력 파일에는 계정 비밀번호가 있으므로 공유하지 않습니다. 이미 존재하는 출력 경로에는 저장하지 않습니다.

```bash
# 15팀, 90명
python3 prepare-teams.py --base-url "$API_URL" --teams 15 --members-per-team 6 --output reports/teams-15.credentials.json

# 20팀, 120명
python3 prepare-teams.py --base-url "$API_URL" --teams 20 --members-per-team 6 --output reports/teams-20.credentials.json

# 50팀, 300명
python3 prepare-teams.py --base-url "$API_URL" --teams 50 --members-per-team 6 --output reports/teams-50.credentials.json

# 100팀, 600명
python3 prepare-teams.py --base-url "$API_URL" --teams 100 --members-per-team 6 --output reports/teams-100.credentials.json
```

### 2. 회의 테스트 자료 준비: `prepare-meetings.py`

앞 단계에서 완료한 팀 파일에 해당하는 명령을 실행합니다. 참여 테스트용 회의를 팀마다 1개 미리 생성하고, 회의 생성 테스트용 요청 정보도 저장합니다. 출력되는 가장 이른 토큰 만료 시각 전에 k6를 실행합니다.

```bash
# 15팀
python3 prepare-meetings.py --base-url "$API_URL" --input reports/teams-15.credentials.json --output reports/fixtures-15.json --scenarios create-join

# 20팀
python3 prepare-meetings.py --base-url "$API_URL" --input reports/teams-20.credentials.json --output reports/fixtures-20.json --scenarios create-join

# 50팀
python3 prepare-meetings.py --base-url "$API_URL" --input reports/teams-50.credentials.json --output reports/fixtures-50.json --scenarios create-join

# 100팀
python3 prepare-meetings.py --base-url "$API_URL" --input reports/teams-100.credentials.json --output reports/fixtures-100.json --scenarios create-join
```

### 3. 회의 생성 API: `api.js` / `SCENARIO=create`

팀마다 회의 생성 요청을 1건씩 보냅니다. 각 명령이 종료되면 해당 HTML 결과가 `reports/`에 저장됩니다.

```bash
# 15팀: 동시 요청 15건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/create-15.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-15.json -e SCENARIO=create -e COUNT=15 api.js

# 20팀: 동시 요청 20건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/create-20.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-20.json -e SCENARIO=create -e COUNT=20 api.js

# 50팀: 동시 요청 50건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/create-50.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-50.json -e SCENARIO=create -e COUNT=50 api.js

# 100팀: 동시 요청 100건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/create-100.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-100.json -e SCENARIO=create -e COUNT=100 api.js
```

### 4. 회의 참여 API: `api.js` / `SCENARIO=join`

팀원마다 참여 요청을 1건씩 보냅니다. 참여용 회의는 `prepare-meetings.py`가 만든 회의를 사용합니다.

```bash
# 15팀 × 6명: 동시 요청 90건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/join-15.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-15.json -e SCENARIO=join -e COUNT=90 api.js

# 20팀 × 6명: 동시 요청 120건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/join-20.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-20.json -e SCENARIO=join -e COUNT=120 api.js

# 50팀 × 6명: 동시 요청 300건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/join-50.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-50.json -e SCENARIO=join -e COUNT=300 api.js

# 100팀 × 6명: 동시 요청 600건
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=reports/join-100.html \
k6 run -e BASE_URL="$API_URL" -e ALLOW_LIVE_TEST=YES -e FIXTURE_FILE=reports/fixtures-100.json -e SCENARIO=join -e COUNT=600 api.js
```

같은 fixture로 생성·참여 테스트를 반복하면 이미 생성된 회의나 참여 기록 때문에 결과가 달라질 수 있습니다. 재측정에는 새 팀 파일과 새 fixture, 새 HTML 파일명을 사용합니다. 요청이 매우 짧게 끝나면 HTML에는 집계 결과만 표시될 수 있습니다.

| 팀 수 | 생성 계정 | 회의 생성 요청 | 회의 참여 요청 |
| --- | --- | --- | --- |
| 15 | 90 | 15 | 90 |
| 20 | 120 | 20 | 120 |
| 50 | 300 | 50 | 300 |
| 100 | 600 | 100 | 600 |

## 파일별 역할과 옵션

### `prepare-teams.py`

회원가입, 팀 생성, 나머지 회원의 팀 가입을 **순차적으로 준비**합니다. `--teams`는 1~100, `--members-per-team`은 1~10입니다. `--delay-ms`의 기본값은 요청 사이 100ms입니다. 출력 파일에는 비밀번호가 들어가며, 기존 출력 파일을 덮어쓰지 않습니다.

### `prepare-meetings.py`

준비된 계정을 다시 로그인하고 회의 테스트용 fixture를 만듭니다. 이번 흐름에서는 `--scenarios create-join`을 사용합니다. 이 과정에서 **참여 테스트용 회의를 팀마다 미리 1개 생성**하고, 별도로 k6 회의 생성 요청 정보도 기록합니다. 출력되는 가장 이른 토큰 만료 시각을 확인한 뒤 k6를 실행하세요.

### `api.js`

`SCENARIO=create`는 회의 생성, `SCENARIO=join`은 회의 참여입니다. `COUNT`가 동시 실행할 VU 수이며 **VU당 요청을 1번** 보냅니다. 같은 생성·참여 fixture로 재실행하면 이미 만들어진 자원이나 참여 상태 때문에 결과가 달라질 수 있습니다.

### `common.js`

k6의 공통 설정 파일로, 직접 실행하지 않습니다. `BASE_URL`, `ALLOW_LIVE_TEST=YES`, `FIXTURE_FILE`, `COUNT`를 검사합니다. `COUNT`를 생략하면 기존 `LEVEL=smoke|target|max`의 고정 수를 사용합니다.

### `prepare-local-auth.py` / `load_test_prep.py`

기존 계정 fixture를 로그인하거나 선택적으로 가입시키는 **별도 준비 방식**입니다. 이번 자동 생성 흐름에서는 실행할 필요가 없습니다. 특히 `load_test_prep.py --prepare-resources` 방식은 입력 팀 수가 20개로 제한되어 있어 50·100팀 단계에는 맞지 않습니다.

### `audio-ws.js` / `sse.js`

각각 녹음 WebSocket과 회의 이벤트 연결을 측정합니다. **이번 회원·팀·회의 생성 및 참여 범위에는 포함하지 않습니다.** `sse.js` 실행에는 `k6/x/sse` 확장이 필요합니다.

회원·팀 준비 작업은 k6 측정 구간 밖에서 순차 실행됩니다. 따라서 위 명령의 동시 부하 결과는 **회의 생성과 회의 참여 각각**에 대한 결과입니다.
